# Errand Agent

A chat agent that arranges home-service errands: plumber, electrician, AC service and more. It runs against mock provider tools. It asks only for missing details, compares providers, and gets explicit approval before any booking, cancellation or reschedule. That approval is enforced in code. It also recovers safely from timeouts, conflicts, crashes and prompt injection.

## Quick start

```bash
make setup                 # venv + deps (Python 3.11+)
make eval                  # all scenarios + contract/regression tests, offline; writes EVAL_TABLE.md
cp .env.example .env       # add ANTHROPIC_API_KEY for live mode
make ui                    # Streamlit: chat left, live trace right, failure-injection controls in sidebar
make chat                  # terminal chat (/trace /memory /state /advance N /quit)
```

To try the UI without an API key, run `ERRAND_OFFLINE_DEMO=1 make ui`. It uses a scripted model for the plumber flow.

## Layout

| Path | What |
|---|---|
| `mocks/tools.py` | The 8 fixed tool contracts as a seeded `MockWorld`. It is the source of truth for holds and bookings. `Scenario` forces outcomes for tests. |
| `agent/orchestrator.py` | The turn loop: context → model → tool dispatch → transitions. Also proposals, approval handling, the claim guard and recovery. |
| `agent/approval.py` | Strict yes/no classifier, and approvals bound to a fingerprint of the material details. |
| `agent/booking.py` | Idempotent book/cancel/reschedule, the `pending_ops` write-ahead log, timeout reconciliation, and `recover()`. |
| `agent/memory.py`, `agent/context.py` | Explicit/inferred/forgotten facts, and a token-budgeted context with a per-turn log. |
| `agent/proactive.py` | Detects provider cancellations and proposes a replacement for approval. |
| `agent/sanitize.py` | Untrusted-data envelope and injection flags. |
| `agent/trace.py`, `agent/limits.py` | JSONL traces, and hard limits on turns, tool calls, wall-clock time and retries. |
| `agent/llm.py` | Claude (`claude-opus-5-5` by default, override with `ERRAND_MODEL`), plus `ScriptedLLM`, `RecordingLLM` and `ReplayLLM` for offline evals. |
| `evals/` | Scenarios with simulated users, 7 global invariants, and the EVAL_TABLE generator. |
| `tests/` | Mock-contract tests (including the 70/15/15 book distribution) and bug regression tests. |
